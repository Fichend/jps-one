# Hunt Copilot 新建任务前端工作台优化

## 本次目标

本次只优化新建搜索任务模块的前端工作台体验，不改动搜索 API、MCP 执行器、MiniMax Planner、候选池或评分后端逻辑。

核心目标：让业务员在一个清晰、稳定、可隐藏历史记录的界面中完成对话式策略确认，避免历史列表常驻挤占空间、聊天区跳动、策略卡流程不清晰。

## 页面结构

- 顶部工作条：页面标题、历史会话按钮、五段式执行进度。
- 左侧主工作区：对话消息、建议回复、固定输入区。
- 右侧策略区：四步策略卡、通道预检状态。
- 历史会话：默认隐藏，通过左侧抽屉打开，支持继续和复制相似策略。

## 四步策略卡

策略卡固定展示四组内容：

1. 目标：地区、客户类型、JPS 产品、排除对象。
2. 硬条件：Instagram、Facebook、邮箱、电话、官网、地址。
3. 数量与预算：预检预算、正式预算、候选池、最终客户。
4. 执行规则：硬过滤、待补全、候选池、多源实体合并。

每一步都显示当前是否已完成或正在确认。缺失字段、冲突提醒和 Strategy Critic 仍由后端返回，前端只负责清晰呈现。

## 交互约束

- 聊天区不再反复刷整张策略卡，策略卡固定在右侧实时更新。
- 历史会话不再常驻页面，减少视觉噪音。
- 输入框在请求处理中仍可编辑，发送按钮负责防止重复提交。
- 消息列表在新消息进入后自动滚动到底部。
- 所有正式动作仍由后端 `allowed_actions` 控制，前端不绕过状态机。

## 验收点

- `npm --prefix frontend run build` 必须通过。
- `/hunts/new` 在桌面宽度下为对话区 + 策略区双栏。
- 移动和窄屏下历史抽屉可打开/关闭，文本不溢出按钮和卡片。
- 确认策略、检查通道、正式执行按钮仍按后端状态启用。
