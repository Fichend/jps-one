# Hunt Copilot 阶段四修复说明

本阶段聚焦“搜索完成后业务员能看懂结果质量”，避免任务结束后只看到一堆客户但不知道是否达标。

## 已完成

- 新增 `candidate_pool/quality.py`：对候选池和最终线索生成质量诊断。
- Hunt 结果接口新增 `candidate_quality_summary`。
- 质量诊断包含：
  - 候选总数、Top N 数量、最终线索数
  - A/B/C/D 等级分布
  - Instagram、Facebook、邮箱、电话、官网、地址等硬条件覆盖率
  - 各搜索通道贡献数量
  - 主要缺口和下一步建议
- 队列任务详情的“候选池”区域新增“候选质量诊断”，业务员可以直接看到本次结果是不是满足策略要求。

## 受控边界

- 本阶段不改变 Tavily / Apify / Google Maps 搜索调用量。
- 不自动放宽硬条件，不自动重跑任务。
- 诊断只基于公开证据字段和 JPS 评分，不伪造缺失联系方式。

## 验收点

- 如果要求 Instagram、邮箱、电话，质量诊断会显示这三项覆盖数。
- 如果 Top N 不足，诊断会明确指出主要缺口。
- A/B/C/D 等级在候选池诊断里可见。
