# JPS One 数据与权限规范

## 1. 数据分类

公开业务数据：

- 公司官网
- 公开邮箱
- 公开电话
- 公开社媒链接
- 公开产品介绍
- 公开目录和行业平台信息

内部业务数据：

- 客户跟进状态
- 负责人
- 产品报价规则
- 业务备注
- 邮件草稿
- 历史任务结果

敏感配置数据：

- API key
- OAuth secret
- SMTP/IMAP 密码
- SSH key
- `API_ACCESS_TOKEN`
- Nginx Basic Auth 密码
- 数据库路径和备份包

## 2. 权限原则

普通业务员：

- 可查看任务看板、历史任务、客户池、产品库、匹配、报价、知识库和配置状态。
- 可新建任务。
- 可查看任务详情。
- 可在有权限时删除历史任务。
- 不可查看系统框架和后台技术规划。

管理员：

- 可进入系统设置。
- 可进入系统框架。
- 可配置渠道和密钥。
- 可部署、备份、回滚。
- 可处理删除和数据恢复。

未来权限应从用户名判断逐步升级为角色表或统一认证系统。

## 3. 历史任务数据规范

历史任务保存位置：

```text
backend/data/hunts
```

每个任务是一个 JSON 文件。

展示规范：

- 任务看板必须展示全部历史任务。
- 按创建日期分组。
- 显示同步总数。
- 显示状态和核心摘要。

删除规范：

- 删除前必须二次确认。
- 未确认删除时不能改变数据。
- 删除后从内存和磁盘删除该任务 JSON。
- 运行中、排队中和待处理任务不能删除。
- 删除操作应刷新任务看板。

恢复规范：

- 如误删，需要从云端备份或系统快照恢复。
- 恢复前先停止继续删除。
- 恢复后重启后端或触发重新加载。

## 4. 密钥与配置规范

密钥不得：

- 写入 README。
- 写入 Word 文档。
- 写入截图。
- 写入前端代码。
- 打印到日志。

密钥可以：

- 保存在云端 `backend/.env`。
- 通过设置页脱敏显示。
- 由管理员手动更新。

发布代码时：

- 不覆盖 `.env`。
- 不把本地 `.env` 上传到云端。
- 如果必须修改某一项配置，先备份 `.env`，只改指定项。

## 5. 外部渠道合规规范

搜索和网页读取：

- 只采集公开信息。
- 不绕过登录。
- 不抓取私密内容。

Meta / Facebook：

- 只使用授权资产和平台允许的接口。
- 不承诺全平台客户搜索。
- 不绕过审核、权限或登录限制。

邮件：

- 默认人工审核。
- 不默认批量自动发送。
- 遵守目标国家反垃圾邮件规则。

## 6. 备份规范

发布前备份：

- 被覆盖代码文件。
- `.env`，如果涉及配置变更。
- 数据库和历史任务，重大变更前必须备份。

备份命名建议：

```text
predeploy-<feature>-YYYYMMDDHHMMSS.tgz
backend-env-predeploy-<feature>-YYYYMMDDHHMMSS.env
```

备份保存在：

```text
/opt/ai-hunter/backups
```

## 7. 审计规范

重要操作需要记录：

- 云端部署。
- 配置变更。
- 删除历史任务。
- 修改权限。
- 接入新的外部渠道。

记录内容：

- 操作时间。
- 操作人或执行者。
- 操作目的。
- 影响范围。
- 备份路径。
- 验证结果。
