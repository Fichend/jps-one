# JPS One 使用规范

## 1. 产品定位

JPS One 是 JPS 医疗外贸智能运营系统，当前核心闭环是：

```text
新建获客任务
→ 搜索和读取公开资料
→ 生成潜在线索
→ 进入历史任务和客户池
→ 匹配 JPS 产品
→ 生成开发信、报价和跟进动作
```

业务员不需要理解 Skill、MCP、RAG、部署、队列、容器和系统框架细节。这些属于管理员和开发维护范围。

## 2. 角色与入口

业务员可见入口：

- 任务看板
- 新建任务
- 客户池
- 产品库
- 匹配中心
- 报价中心
- 知识库
- 配置中心

管理员额外可见入口：

- 系统设置
- 系统框架
- 后台配置和部署状态

普通业务员不得看到：

- 系统框架
- 下一步技术规划
- Skill/MCP/RAG 内部结构
- 密钥、token、SSH、Nginx、Docker、数据库路径
- 后台排障说明

## 3. 任务看板使用规范

任务看板是业务员的第一入口，必须保持可读、可操作、可追溯。

看板内容：

- 任务队列状态
- 自动执行器状态
- 新增企业统计
- 邮件发送统计
- 飞书通知状态
- 近期失败、发送、回复事件
- 历史任务

历史任务规范：

- 所有历史任务必须显示在任务看板。
- 历史任务按创建日期分组。
- 每个日期组展示该日期任务数量。
- 历史任务卡片显示标题、状态、线索数、邮件序列数、地区、官网、轮次和详情入口。
- 历史任务卡片右下角提供删除入口。

删除规范：

- 默认保留，不自动删除。
- 点击 `删除` 后必须出现 `确认删除` 和 `不删除`。
- 点击 `不删除` 只取消确认，不改变数据。
- 点击 `确认删除` 才删除该历史任务。
- 运行中、排队中或待处理任务不得删除。
- 删除后任务看板应刷新历史任务数量。

## 4. 新建任务规范

新建任务时应尽量填写：

- 官网或品牌网址
- 产品关键词
- 目标客户画像
- 目标国家或地区
- 目标线索数
- 是否需要邮件草稿
- 附件资料，如果对产品或客户画像有帮助

输入建议：

- 产品关键词应具体，例如 `dental simulator`、`medical tape`。
- 目标客户画像应写清楚买家类型，例如进口商、经销商、医院采购、学校实验室。
- 地区必须明确到国家或区域。
- 不要输入隐私数据、未公开客户名单或不应采集的信息。

## 5. 配置中心使用规范

配置中心只展示渠道可用状态，不展示后台技术规划。

业务员可以查看：

- 搜索渠道
- 网页读取
- Meta / Facebook 状态
- 邮件发送状态
- 邮件回复检测状态
- 飞书通知状态

业务员不应操作：

- OAuth App Secret
- API key
- SMTP/IMAP 密码
- Nginx 配置
- Docker 配置
- 系统框架和部署状态

Meta / Facebook 说明：

- 浏览入口打通不等于业务可用。
- 可用性取决于授权资产、页面、权限、审核和平台规则。
- 第一阶段只作为授权资产、Lead Ads、页面或消息补充渠道，不承诺全平台客户搜索。

## 6. 邮件使用规范

默认策略：

- 系统生成开发信草稿。
- 业务员或管理员审核后再发送。
- 不默认批量自动发送。

发送前必须确认：

- SMTP 已配置并测试通过。
- 发件人名称为 `JPS One` 或 JPS 指定业务身份。
- 收件人邮箱来自公开来源或合规业务来源。
- 邮件内容无敏感价格泄露、虚假承诺和不合规表述。

回复检测前必须确认：

- IMAP 已配置并测试通过。
- 回复检测不会误读非业务邮箱。

## 7. 客户池、产品库、匹配和报价规范

当前这些模块是业务地基，后续逐步接入真实数据。

客户池：

- 保存潜在客户、联系人、国家、证据、负责人和跟进状态。
- 不保存无来源、无证据的联系人。

产品库：

- 保存 JPS 产品、型号、卖点、MOQ、价格规则和适用客户类型。
- 价格敏感信息只给授权角色查看。

匹配中心：

- 给出客户与 JPS 产品的匹配理由。
- 推荐必须有证据引用。

报价中心：

- 报价草稿必须可追溯。
- 价格规则和审批流程不能绕过。

## 8. 日常使用检查

每天开始使用前：

- 看任务看板是否能打开。
- 看历史任务是否显示数量。
- 看配置中心搜索和网页读取是否可用。
- 看是否有失败任务需要处理。
- 看邮件发送和回复检测是否处于预期状态。

出现异常时：

1. 记录页面、时间和操作。
2. 不重复点击删除或发送。
3. 通知管理员检查配置和日志。
4. 不自行修改 `.env` 或云端服务。
